목적: 다른 PC에서 `git pull`(또는 `git clone`) 후 **CMake 재구성 + 빌드**가 바로 되도록, 현재 프로젝트가 참조하는 모든 외부 include/lib/dll을 한 곳에 정리한다.

2. **CMake 3.20 이상** (현재 PC엔 4.4.2 설치되어 있으나 `cmake_minimum_required(VERSION 3.10)`이 명시 최소치이며, README 등에서 3.20+ 권장)
3. **vcpkg (classic mode, manifest 아님)** — `vcpkg.json`이 저장소에 없으므로 패키지를 수동으로 설치해야 함. 아래 2절 참고.
4. **CMake 재구성 시 vcpkg 툴체인 파일 지정 필수**:
   ```
   -DCMAKE_TOOLCHAIN_FILE=<vcpkg 경로>/scripts/buildsystems/vcpkg.cmake
   ```

## 3. CMake Include / Link 상세

### 3-1. Include 디렉토리

- **vcpkg 쪽**: 별도로 `include_directories()`를 직접 쓰지 않고, `find_package(SDL2/SDL2_image/SDL2_ttf/JPEG/Iconv ...)`가 vcpkg 툴체인 파일을 통해 자동으로 `<vcpkg>/installed/x64-windows/include`를 넣어준다 (실제 컴파일 옵션에는 `/external:I ".../installed/x64-windows/include"` 형태로 나타남).
  - 예외: macOS(Homebrew)용으로 `/opt/homebrew/include/SDL2`, `/usr/local/include/SDL2`를 `project()` 호출 전에 수동으로 `CMAKE_CXX_FLAGS`/`include_directories()`에 추가하는 코드가 있음(Windows에서는 해당 없음, `CMakeLists.txt:4-8`, `:64-68`).
- **프로젝트 내부 include 경로** (직접 `target_include_directories`로 지정): `basic/`, `Client/`, `Client/TextSystem/`, `Client/DXLib/`, `Client/SpriteLib/`, `Client/framelib/`, `Client/Packet/`, `Client/WinLib/`, `VS_UI/`, `VS_UI/src/header/`, `VS_UI/src/widget/`, `VS_UI/src/hangul/`, `VS_UI/src/Imm/`(Windows 전용) — 저장소 안에 있으므로 `git pull`만으로 해결됨.
- **ATL include** (Windows 전용): 설치된 VS 인스턴스에서 `**/VC/Tools/MSVC/*/atlmfc/include`를 글롭으로 찾아 자동 추가 (`CMakeLists.txt:298-320`). 하드코딩된 경로가 아니라 매 PC에서 자동 탐색하므로 이식성 문제는 없음 — 단, ATL 컴포넌트 자체가 설치되어 있어야 검색이 성공한다.

### 3-2. Link 라이브러리

- **vcpkg 라이브러리** (import lib, `find_package`가 타깃으로 노출): `SDL2::SDL2`, `SDL2::SDL2main`, `SDL2_image::SDL2_image`, `SDL2_ttf::SDL2_ttf`, `SDL2::SDL2_mixer`(있을 때만), `Iconv::Iconv`(못 찾으면 `iconv` 문자열로 폴백), `${JPEG_LIBRARIES}`.
- **Windows 시스템 라이브러리** (vcpkg 불필요, Windows SDK에 내장): `ws2_32`(Winsock), `winmm`(WavePackFileManager의 mmio*), `wininet`(MInternetConnection), `comctl32`(공용 컨트롤), `netapi32` — `DarkEden` 타겟에만 링크 (`CMakeLists.txt:764-772`).
- **ATL 라이브러리**: `atls.lib` — `atlbase.h`의 `#pragma comment(lib, "atls.lib")`가 요구. `_atlmfc_lib_dir`(자동 탐색된 `atlmfc/lib/x64`)를 `DarkEden` 타겟의 링크 디렉토리에 추가해서 해결 (`CMakeLists.txt:742-744`).

## 4. 런타임에 필요한 DLL

vcpkg의 `x64-windows` triplet은 동적 링크이므로, 빌드된 `DarkEden.exe`가 실행되려면 다음 DLL들이 같은 폴더(`bin/Debug` 등)에 있어야 한다.

**자동화됨**: `CMakeCache.txt`에 `VCPKG_APPLOCAL_DEPS:BOOL=ON`이 설정되어 있어서, `DarkEden`(및 각 viewer 도구) 빌드 후 MSBuild 포스트빌드 단계에서 `vcpkg/scripts/buildsystems/msbuild/applocal.ps1`이 실행되어 필요한 DLL을 실행 파일 옆에 **자동 복사**한다. 즉, 새 환경에서도 정상적으로 vcpkg + CMake로 빌드만 하면 수동으로 DLL을 옮길 필요는 없다.

현재 `build/vs2019/bin/Debug/`에 실제로 복사되어 있는 DLL (Debug 빌드 = `d` 접미사):

```
SDL2d.dll
SDL2_ttfd.dll
freetyped.dll
libpng16d.dll
zlibd1.dll
brotlicommon.dll
brotlidec.dll
bz2d.dll
jpeg62.dll
```

> `SDL2_imaged.dll`, `SDL2_mixerd.dll`은 vcpkg에는 설치되어 있지만 현재 이 폴더엔 복사되어 있지 않음 — `DarkEden.exe`가 실제로 그 심볼을 참조하지 않아 applocal 스크립트가 불필요하다고 판단한 것으로 보인다(정적 라이브러리 링크 특성상 미사용 심볼은 배제됨). 추후 SDL_image/SDL_mixer 관련 코드를 실제로 호출하도록 수정하면 자동으로 다시 나타난다. 문제가 생기면 `<vcpkg>/installed/x64-windows/debug/bin/`에서 수동 복사하면 된다.

## 5. 새 환경에서 반드시 주의할 점 (하드코딩된 절대경로)

`build/vs2019/*.vcxproj`, `*.sln` 파일들이 **git에 커밋되어 있다** (`.gitignore`는 `CMakeCache.txt`/`CMakeFiles/`만 제외하고 `.vcxproj`는 제외하지 않음). 그런데 이 파일들은 CMake가 **이 PC의 절대경로를 그대로 박아서** 생성한 것이다:

- vcpkg 경로: `H:/Source/GithubDesktop/vcpkg_download/vcpkg/...` (include 경로, `applocal.ps1` 호출 인자 등 여러 곳)
- 저장소 자체 경로: `H:/Source/GithubDesktop/dk_client/build/vs2019/bin/...` (`applocal.ps1`의 `-targetBinary` 인자 등)

즉 다른 PC에서 `git pull` 직후 **커밋된 `.sln`/`.vcxproj`를 그대로 열어서 빌드하면, 드라이브 문자나 폴더 구조가 다르면 실패한다.**

**권장 절차** (다른 PC/환경에서):

1. vcpkg를 아무 위치에나 설치하고 2절의 패키지를 설치한다.
2. 기존 `build/vs2019/` 폴더를 지우고 CMake로 재생성한다:
   ```powershell
   Remove-Item -Recurse -Force build\vs2019
   cmake -S . -B build\vs2019 -G "Visual Studio 16 2019" -A x64 `
     -DCMAKE_TOOLCHAIN_FILE=<내 vcpkg 경로>\scripts\buildsystems\vcpkg.cmake `
     -DCMAKE_BUILD_TYPE=Debug
   cmake --build build\vs2019 --config Debug
   ```
   (`make debug`/`make debug-asan`은 `build/debug`, `build/debug-asan`처럼 다른 폴더를 쓰므로 `build/vs2019`와 별개로 항상 안전하게 재생성 가능)
3. 굳이 VS2019 IDE에서 `.sln`으로 작업하고 싶다면, 1번처럼 CMake로 새로 생성된 `.sln`을 열 것 — 커밋되어 있던 기존 `.sln`을 그대로 쓰지 말 것.

같은 이유로, **드라이브 문자/폴더명이 이 PC(`H:\Source\GithubDesktop\...`)와 동일한 다른 PC**라면 커밋된 `.vcxproj`를 그대로 써도 vcpkg 경로만 동일하게 맞추면 우연히 동작할 수 있으나, 이는 우연이지 보장된 동작이 아니다.

### 향후 개선 아이디어 (참고용, 이번 조사에서 실행하지는 않음)

- `vcpkg.json` 매니페스트 모드로 전환하면 vcpkg 경로를 하드코딩하지 않고 `CMakeLists.txt`에서 `VCPKG_ROOT` 환경변수만으로 패키지 자동 설치가 가능해짐.
- `build/` 디렉토리 전체를 `.gitignore`에 추가하고 `.vcxproj`/`.sln`을 커밋 대상에서 제외하면(각 PC에서 CMake로만 생성하도록 강제) 위 절대경로 문제가 원천 차단됨.
