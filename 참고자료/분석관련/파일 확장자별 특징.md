# Data 디렉토리 파일 확장자별 특징

조사 대상: `build/vs2019/bin/Debug/Data` 하위 전체 파일
조사 방법: 소스코드 grep (`.spk`, `.sspk` 등 리터럴 문자열 및 매크로 정의) + 실제 파일 바이너리 헤더 확인

관련 문서: [[직접분석) sspk ,spk 차이]]

---

## 1. 확실하게 근거를 찾은 확장자 (소스 코드에 로딩 로직/매크로 존재)

### 1-1. 스프라이트(이미지) 계열 - Pack + Index 쌍 구조

공통 저장 포맷은 `Client/SpriteLib/CTypePack.h`의 `CTypePack` / `CTypePack2` 템플릿을 사용한다.
- 데이터 파일: `WORD(2byte) 개수` + 각 항목의 실제 데이터가 순서대로 저장됨
- 인덱스 파일: `WORD(2byte) 개수` + 각 항목의 파일 오프셋(`DWORD`, 4byte)이 저장됨. 파일명은 데이터 파일명 뒤에 `i`를 붙인 것과 동일 (`CTypePack::SaveToFile`, `CTypePack::LoadFromFileRunning` 참고)
- 인덱스 파일이 있으면 전체를 한번에 읽지 않고 필요한 항목만 지연 로딩(Running Load)할 수 있다.

| 확장자 | 짝 인덱스 | 담당 클래스 | 용도 |
|---|---|---|---|
| `.spk` | `.spki` | `CSpritePack` (`CTypePack2<CSprite, CSprite555, CSprite565>`) | 일반 오브젝트/UI 이미지 스프라이트 모음 (타일, UI, 캐릭터 UI 파츠 등 대부분) |
| `.ispk` | `.ispki` | `CIndexSpritePack` (`CTypePack2<CIndexSprite,...>`) | 인덱스 컬러(팔레트 기반) 스프라이트 - `Addon.ispk`, `Creature.ispk`, `Ousters.ispk` 등 캐릭터/애드온(장비) 이미지 |
| `.aspk` | `.aspki` | `CAlphaSpritePack` | 알파블렌딩(반투명) 이미지 - 이펙트 등 |
| `.sspk` | `.sspki` | `CShadowSpritePack` | 그림자 전용 스프라이트 (일반 스프라이트보다 정보가 단순, 색상 없이 그림자 형태만 저장). `MTopView.h`의 `m_AddonSSPK`, `m_CreatureSSPK` 등 멤버로 사용 |

> `직접분석) sspk ,spk 차이.md`에서 이미 확인된 내용과 일치: `spk`=오브젝트 이미지, `sspk`=Shadow Sprite.

### 1-2. 프레임(애니메이션 정의) 계열 - Pack + Index 쌍 구조

`Client/framelib/CFramePack.h`의 `CFramePack<Type>` 템플릿 사용. 저장 포맷은 스프라이트 팩과 유사(개수 + 오프셋 인덱스)하지만, 내용물은 실제 이미지가 아니라 "어떤 스프라이트ID를 몇 번째 프레임에 사용하는지"에 대한 애니메이션 정의 데이터다.

| 확장자 | 짝 인덱스 | 담당 타입 | 용도 |
|---|---|---|---|
| `.ifpk` | `.ifpki` | `CImageFramePack` (`CFramePack<CFrame>`) | 방향성 없는 단일 이미지 프레임 (ItemTile, ImageObject 등) |
| `.afpk` | `.afpki` | `CAnimationFramePack` / `CDirectionFramePack` | 방향성 있는 애니메이션 오브젝트 프레임 (AnimationObject, InteractionObject 등) |
| `.efpk` | `.efpki` | `CEffectFramePack` (`CFramePack<DIRECTION_EFFECTFRAME_ARRAY>`) | 방향성 있는 이펙트 프레임 (Effect, EffectScreen, NormalEffect, ShadowEffect) |
| `.cfpk` | `.cfpki` | `CCreatureFramePack` (`CFramePack<ACTION_FRAME_ARRAY>`) | 액션(Action) + 방향성을 모두 갖는 크리처 애니메이션 프레임. 몬스터/캐릭터/장비(Addon)의 동작(걷기, 공격 등) 정의 |

### 1-3. 팔레트 계열

| 확장자 | 짝 인덱스 | 담당 타입 | 용도 |
|---|---|---|---|
| `.ppk` | `.ppki` | `MPalettePack` (`CTypePack2<MPalette, MPalette555, MPalette565>`) | 인덱스 컬러 이미지용 팔레트 모음. `Effect.ppk`, `EffectScreen.ppk` 등 알파 이펙트 색상 테이블 (`EffectResourceContainer::LoadPalettePacks` 참고) |

### 1-4. 필터 계열

| 확장자 | 담당 클래스 | 용도 |
|---|---|---|
| `.ft` | `CFilter` / `CFilterPack` | 픽셀 단위 밝기/색 변화 값을 담은 2차원 필터 (조명 효과 등). `ImageObject.ft` |
| `.ftp` | `CFilter` / `CFilterPack` | `.ft`와 동일 계열, Light2D/Light3D용 조명 필터 (`Light2D.ftp`, `Light3D.ftp`) |

### 1-5. 리소스 압축 아카이브 (RAR 기반)

| 확장자 | 담당 클래스 | 용도 |
|---|---|---|
| `.rpk` | `CRarFile` (`VS_UI/RarFile.h/cpp`) | 원래는 암호(`RPK_PASSWORD`)가 걸린 RAR 압축 파일. 텍스트/XML 리소스(퀘스트, 도움말, 스킬 설명, 책 등)를 담는다. 현재 포팅된 코드는 unrar 의존성 제거를 위해 "같은 이름의 압축 해제된 디렉토리"를 읽는 방식으로 대체됨 (`Data/Ui/txt/Item.rpk` → `Data/Ui/txt/Item/`). `Book.rpk`, `Help.rpk`, `Skill.rpk`, `TutorialEtc.rpk`, `title.rpk`, `infodata.rpk` 등 |

### 1-6. 포스 피드백(햅틱) 계열

| 확장자 | 담당 라이브러리 | 용도 |
|---|---|---|
| `.ifr` | Immersion `ImmIFR.h` (FEELit IFR 프로젝트 포맷) | DirectInput 포스피드백(진동) 이펙트 정의 프로젝트 파일. `VS_UI/src/Imm/` 햅틱 라이브러리가 로드. `ui.ifr`, `action.ifr`, `skill.ifr`, `inventory.ifr`, `useitem.ifr` - UI/전투 상황별 진동 패턴 정의 |

### 1-7. 기타 확인된 텍스트/설정 계열

| 확장자 | 용도 |
|---|---|
| `.inf` | Properties(`key : value`) 포맷의 설정/데이터 정의 파일. `FileDef.inf`(리소스 경로 정의, `MFileDef.h`/`g_pFileDef->load()`로 로드), `GameClient.inf`, `Item.inf`, `Skill.inf` 등 대부분의 게임 정의 데이터 |
| `.map` | Zone(맵) 데이터. 헤더에 `"MAP_2000_05_10"` 시그니처 문자열 포함, 이후 zone id/버전/가로세로 크기/섹터 배열이 이어짐 (`tools/engine/sprite/src/zone.c`가 파싱 로직 보유) |
| `.sec` | `FileDef.sec` - `FileDef.inf`와 동일 정보를 담은 것으로 추정되는 보조/보안(암호화) 버전 파일. 클라이언트 소스에서 직접 로드하는 코드는 발견되지 않음(원본 상용 버전에서 무결성 체크용으로 쓰였을 가능성) |
| `.scc` | `vssver.scc`, `vssver2.scc` - **게임 리소스 아님**. Visual SourceSource Safe(VSS) 소스 관리 도구가 남긴 메타데이터 파일 |

## 2. 파일만 존재하고 현재 소스에서 직접적인 로딩 근거를 찾지 못한 확장자

아래 항목들은 `Data` 폴더에 실제 파일은 존재하지만, 현재 포팅된 클라이언트 소스(C++/문자열 리터럴 기준)에서 해당 확장자를 여는 코드를 찾지 못했다. 파일 위치·이름 패턴·바이너리 헤더를 근거로 한 추정이며, 재탐색은 하지 않았다(요구사항 4번).

| 확장자 | 위치 | 추정 |
|---|---|---|
| `.mip` | `Data/Map/*.mip` | 맵과 동일한 파일명으로 존재(`asylion_dungeon.mip` 등). 헤더가 `.map`과 달리 가로/세로 크기(예: `0x0080 0x0080`)로 시작하고 파일 크기가 매우 작아(수백 byte), 맵 미니맵/썸네일용 압축 이미지로 추정. 이름상 "Map Icon/Image Pack"의 약자로 보임 |
| `.smp` | `Data/Map/*.smp` | `.map`과 동일한 `"MAP_2000_05_10"` 헤더 시그니처를 공유하지만 크기가 훨씬 작음. 섹터 단위로 축약된 보조 맵 정보(예: 이동 가능 여부 등 단순 속성만 담은 축소판)로 추정. "Sector Map(Pack)"의 약자로 보임 |
| `.ssi` | `Data/Map/*.ssi` | 파일 크기가 4byte 수준으로 매우 작음(버전/카운트 값 하나 정도). "Sector/Sub-map Special Info" 등의 약자로 추정되나 근거 불충분 |
| `.spi` | `Data/Image/effectscreen.spi` | `.aspk`/`.ppk` 계열과 이름 패턴이 유사. "Sprite Info" 또는 팔레트/스프라이트 부가 정보로 추정되는 레거시 파일로 보이나, 현재 로딩 코드가 `.ppk`/`.efpk`/`.aspk`만 참조하므로 사용되지 않는 잔존 파일일 가능성이 높음 |
| `.sppk` / `.sppki` | `Data/Image/effectscreen.sppk(i)` | `EffectScreen`용 Shadow/Screen Sprite Pack의 옛 이름으로 추정(현재 코드는 `EffectScreen.spk`/`.efpk`/`.ppk`를 사용). 리팩토링 이전 잔존 파일로 보임 |
| `.sppi` | `Data/Image/effect.sppi`, `EffectScreen.sppi` | 위 `.sppk`와 짝을 이루는 인덱스 또는 부가 정보 파일로 추정 |
| `.ispkii` | `Data/Image/Ousters.ispkii` | `Ousters.ispk`/`.ispki`와 이름이 겹쳐 오타 또는 중복 백업 파일로 보임. 단일 파일만 존재하여 정식 포맷이라기보다 실수로 남은 파일일 가능성이 큼 |

> 위 표의 항목들은 게임 실행에 필수적인 최신 포맷이 아니라, 과거 개발/리소스 제작 도구(맵 에디터 등 이 저장소에 포함되지 않은 별도 툴)가 생성한 중간 산출물이거나, 리팩토링 후 정리되지 않고 남은 레거시 파일일 가능성이 높다. 정확한 포맷을 확정하려면 원본 리소스 제작 툴(현재 저장소에는 없음) 소스가 필요하다.

## 3. 참고: 사운드 계열 (정의만 존재, 현재 미사용)

`MFileDef.h`에 주석 처리된 상태로 `FILE_WAVE_PACK_SOUND` (`Sound.wpk`) / `FILE_WAVE_PACK_SOUND_INDEX` (`Sound.wpki`) 정의가 남아있으나, 현재 SDL_mixer 기반 사운드 시스템(`Client/DXLib/`)은 `.wav`/`.ogg`/`.mid` 원본 파일을 직접 재생하며 `.wpk` 패킹 포맷은 사용하지 않는 것으로 보인다.
